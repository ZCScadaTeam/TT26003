## 二、系统概述

本系统是 THA26001 检测设备的上位机数据采集软件。设备完成一次产品检测后，检测结果（产品码、码等级、总结果、导通耐压、针高、位置度、扫码、是否复检等）由 PLC 暂存，上位机自动读取并保存到本机数据库，同时提供：

- **实时监控**：主界面双通道实时结果 + PLC 通讯状态；
- **数据存储**：每条检测记录自动落库，不依赖人工录入；
- **生产统计**：按小时 / 班组 / 天统计 OK、NG 数量与良率，支持图表、表格两种呈现；
- **明细查询与导出**：当日全部检测明细可导出 Excel / CSV，供报表与追溯使用；
- **数据追溯**：按产品码精确检索某一件产品的完整检测数据；
- **操作日志**：记录系统运行与参数变更，便于故障排查；
- **用户与权限**：按身份区分可用功能，配置类操作有权限门槛。

> **一句话理解**：设备检测 → 自动采集 → 自动存库 → 随时查、按需导出、可单件追溯。

## 三、核心业务流程

### 3.1 开机启动流程

```text
启动程序 → 显示"系统加载中..."进度条 → 加载完成 → 自动进入【主页】
```

- 启动过程无需人工干预，进度条走满后自动进入主界面。
- 系统启动时站别固定为 `All`（全站别模式），**不再弹出站别选择窗口**。
- 进入主界面后，PLC 采集服务在后台自动尝试连接设备；连接失败不影响程序使用，系统会每隔 3 秒自动重连，网络恢复后自动恢复采集。

### 3.2 一次产品检测的完整流程

```text
① 设备完成检测，PLC 将结果写入数据区
        ↓
② PLC 置"采集触发"位 = 1（表示新数据已就绪）
        ↓
③ 上位机轮询读到此标志，读取双通道全部检测数据
        ↓
④ 上位机把"采集触发"位写回 0（复位），通知 PLC 可以准备下一件
        ↓
⑤ 上位机解析数据 → 写入本地数据库
        ↓
⑥ 主界面实时卡片、检测记录表、累计 OK/NG、实时消息同步刷新
```

**触发值含义（现场排查时会用到）**

| 触发值 | 含义              |
| --- | --------------- |
| 0   | 无采集请求，仅刷新界面实时显示 |
| 1   | 采集**产品 1** 数据   |
| 2   | 采集**产品 2** 数据   |
| 3   | **双通道同时采集**     |

> 无论读取是否成功，上位机都会在采集后把触发位复位为 0，避免 PLC 一直等待。

### 3.3 检测记录的落库规则（重要）

| 情形        | 处理方式                                                                  |
| --------- | --------------------------------------------------------------------- |
| 产品码**非空** | 按产品码**覆盖更新**：同一产品码再次被采集时，更新该条记录的全部检测值并刷新"更新时间"，但**保留最原始的"创建时间"和记录位置** |
| 产品码**为空** | **每条独立保存为一条记录**，不与其他空产品码合并                                            |

**这条规则的实际意义**：

- 同一件产品复检多次，数据库里**只保留最新一次检测结果**，但"创建时间"仍是首次采集时间 —— 因此看"创建时间"是首次上机时刻，看"更新时间"是最近一次复检时刻。
- 产品码列出现空值行通常是 PLC 未取到码或扫码失败，属于有效数据，不要当作异常记录删除。

### 3.4 数据统计与查询流程

```text
进入【统计】→ 选择"统计方式"（按小时 / 按班组 / 按天）
        ↓
勾选需要的视图（图表视图 / 表格视图 / 详细数据 / 数据追溯，四者互斥）
        ↓
（表格 / 详细数据视图）选择要看的日期
        ↓
点击【查询】→ 图表与表格按所选维度重新统计并显示
```

- **切换"统计方式"下拉框会自动触发一次查询**，无需再点【查询】。
- **切换"选择日期"也会自动刷新**表格与明细数据。
- 明细视图默认只展示当日数据；导出时导出的是**当日全量明细**，不受界面显示条数限制。

### 3.5 数据追溯流程（单件追溯）

```text
进入【统计】→ 勾选【数据追溯】
        ↓
在"产品码"输入框填入要追溯的产品码（支持完整码值）
        ↓
点击【追溯查询】
        ↓
下方表格显示该产品码的完整检测记录（含全部测量字段）
```

- 追溯查询按**产品码精确匹配**，不做模糊查询，输入必须与数据库中保存的码值一致。
- 因落库规则为"同码覆盖"，同一产品码**只会返回一条记录**（最新一次检测结果）。
- 查不到时会提示"未找到产品码 XXX 的检测记录"，此时应先确认产品码是否正确、该产品是否确实在本机检测过。

### 3.6 每日追溯报表（自动）

上传站每落库一条产品记录，就追加进当日 Excel 报表，不需要人工导出。

| 项目 | 规则 |
| --- | --- |
| 文件名 | `追溯报表_YYYYMMDD.xlsx`（按自然日，例：`追溯报表_20261017.xlsx`） |
| 默认目录 | `D:\追溯数据`；可在【配置 → 追溯报表 / 本地数据保留】改为任意目录（支持 `%ENV%` 与相对路径） |
| 零点换日 | 每天 00:00 自动把前一天结算落盘，并新建当日文件（即使 0 条记录也生成表头） |
| 追加写入 | 记录落库后进报表队列，固定**每 60 秒**写一次（可配置）；写入为**整份原子替换**，任何时刻打开都是完整文件 |
| 重启补写 | 进程重启后按 SQLite 里当天的记录整份重写，**不漏不重**（按雪花 Id 去重）；昨天文件行数不足时同样补齐 |
| 列定义 | 99 列，与统计页导出的 Excel/CSV 完全一致（**采集时间** / 产品码 / 总结果 / **扫码结果** / 三个结果字 / 是否复检 / 上针高 15 点 / 下针高 15 点 / 上位置度 15×X·Y / 下位置度 15×X·Y / 更新时间）；不含记录ID、打码结果、读码结果、打码时间、读码时间、上传结果、创建时间 |
| 保留期 | 本地数据保留 30 天（可配置，`0`=永不删除）：程序退出时先检查，有超过保留期的数据才弹出「正在清理本地数据」进度窗（转圈 + 当前阶段），清完自动退出；没有旧数据直接退出 |

> 报表文件被 Excel 打开时无法替换，程序会保留未落盘数据并每 30 秒提示一次重试；关闭 Excel 后自动补上。即使整天被占用也不会丢数据 —— 队列与 SQLite 里都还在，次日零点或下次启动会写全。

`--selftest` 自检覆盖：文件名规则、当日追加、重复不重、**定时落盘（不手动 Flush）**、零点自动新建、迟到记录重建、**退出前旧数据检查（HasExpired）与清理进度**。



```text
点击右上角关闭按钮 → 弹出"确认退出"对话框 → 点击【确定】
        ↓
有超过保留期（默认 30 天）的本地数据？
  ├─ 有 → 弹出「正在清理本地数据」进度窗（转圈 + 当前阶段）→ 清理完成 → 程序关闭
  └─ 没有 → 直接关闭程序（不弹清理窗）
```

> 直接点击关闭按钮**不会立刻退出**，必须先通过确认对话框，防止误触导致采集中断。
> 退出前会先把当日报表队列里的记录落盘，再检查旧数据；清理失败的异常不会阻止退出。

## 五、各功能模块与操作按钮详解

### 5.1 主页（主页面）

主界面分三个区域：上方双通道实时结果与 PLC 状态、中部检测记录表、底部实时消息。

#### （1）产品 1 / 产品 2 实时结果卡片

展示最近一次采集的检测结果，字段含义如下：

| 显示项  | 含义                                       |
| ---- | ---------------------------------------- |
| 产品码  | 产品唯一标识（由 PLC 提供）                         |
| 码等级  | 码的等级：**A** 或 **B**                       |
| 总结果  | 该件产品的最终判定：**OK** 或 **NG**（OK 绿色 / NG 红色） |
| 导通耐压 | 导通耐压项判定：OK / NG                          |
| 针高   | 针高项判定：OK / NG                            |
| 位置度  | 位置度项判定：OK / NG                           |
| 扫码   | 扫码项判定：OK / NG                            |
| 是否复检 | 该件是否为复检品：**是** / **否**                   |

> 各分项结果为 `--` 表示 PLC 未给出该判定值（通常为该项未检测或数据尚未就绪）。

#### （2）设备状态卡片

卡片顶部一行三格，样式与口径完全一致（绿 = 已连接 / 红 = 未连接 / 灰 = 尚未探测）：

| 显示项 | 含义与使用要点 |
| --- | --- |
| PLC | **已连接**（绿）/ **未连接**（红）。数据不更新时先看这里 |
| 扫码枪 | 基恩士 SR-1000（TCP/IP）。**已连接**（绿）/ **未连接**（红） |
| 打码机 | 大族激光（TCP/IP）。同上 |

判定方式：后台每 5 秒对扫码枪与打码机各做一次 TCP 连通性探测（周期 `DeviceProbeIntervalMs` 默认 5000ms，单次超时 `DeviceProbeTimeoutMs` 默认 1000ms）；已有长连接时直接复用、不另建连接。

> 探测与 PLC 采集互不影响：外设显示“未连接”不影响产线运行，以实际打码/读码结果为准。

其余显示项：

| 显示项   | 含义与使用要点                                          |
| ----- | ------------------------------------------------ |
| 心跳    | 上位机每 0.5 秒向 PLC 发送一次在线信号；此数值正常跳动说明通讯链路正常         |
| 触发    | 采集触发位当前值。正常生产时应在 0 / 1 之间变化；长时间停在 0 表示 PLC 未请求采集 |
| 累计 OK | **本次程序运行期间**采集到的 OK 总数（程序重启后清零，历史数量请看统计页）        |
| 累计 NG | 本次程序运行期间采集到的 NG 总数（同上）                           |

#### （3）检测记录表

显示最近的检测记录，便于现场即时核对。列包括：**采集时间**、产品码、总结果、**扫码结果**、导通耐压结果、针高结果、位置度结果、是否复检，以及全部测量值（上/下针高 Pin1~15、上/下位置度 PIN1~15 X/Y）。

> **扫码结果**是本表的正式字段（读码站判定：OK / NG / `--` 未扫码）。
> **总结果的算法**：四项结果（导通耐压 / 针高 / 位置度 / 扫码）里**没有 NG → OK**；任一项 NG → NG；测量三项（耐压/针高/位置度）缺项 → `--`（不猜 OK）；扫码为空（未扫码）不阻塞 OK。
>
> **三站并行（2026-10 起）**：打码 / 读码 / 上传各有**独立作业队列与独立消费循环**，站内串行、站间并行。
> 打码机（`:1024`）与扫码枪（`:9004`）是两台独立设备，设备层各自的 `SemaphoreSlim` 只锁自己那条连接，
> 因此「打码触发 + 读码触发同时到来」时两站同时开始，单件节拍 = `max(打码, 扫码) + 上传`
> （原来串行是 `打码 + 扫码 + 上传`，打码 1.3s + 扫码 5s 时要 6.3s，现在 5.0s）。
> 在制上下文拆成两份不可变快照：`MarkCtx`（打码站写）/ `ScanCtx`（读码站写），上传站 `Interlocked.Exchange`
> 「读并清空」，两站并行时互不覆盖；码索引的「查存在→登记」「判重码→标记已读」在 `ThaCodeStore` 内用静态锁串行化。
>
> **读码站判定链（2026-10 起）**：① 先分「扫码枪扫上了没」——枪回包命中 `ERROR` 等关键词（`ScannerNoReadKeywords`）= 没扫上 → 自动重试 3 次，仍失败写 `%MW10522=2` + 弹窗「扫码枪未扫到码」；
> ② 扫上了 → 读 PLC 附带前站镭码 `%MW10580`（40WORD）与枪码**比对**，不一致写 `%MW10522=2` + 弹窗「扫码枪：A / PLC搬运获取产品码：B / 不一致」；
> ③ 一致 → 查库重码（已上传 / NG冻结 / 在制超时），重码写 `%MW10522=2` + 弹窗；④ 全过 → `%MW10522=1`。
> 三类 NG（未扫到 / 错码 / 重码）在产品记录里都记 **扫码结果 = NG(2)**，细分原因写读码流水 `ThaScanLog`（`Result` 3=重码 4=错码 5=枪异常 6=MES异常 7=未扫到，`PlcCode` 存 PLC 附带码）。
> 打码结果与打码/读码时间不在本表之外的地方也不落库：只写运行日志、`ThaMarkLog` / `ThaScanLog` 流水和主页三站状态卡。

使用要点：

- 表格**只读**，记录**按产品码去重**：同一产品码再次采集时，该行会被更新并移到表格最上方。
- **完整历史记录请到【统计】页查询**，本表仅作实时查看用。
- 表格可拖拽列宽，但不可拖动排序、不可编辑。

#### （4）实时消息

页面底部显示最近 **5 条**采集消息，格式为：`时间 + 通道号 + 采集：产品码 → 总结果`。用于快速确认最近几件的判定走向。打码失败时此处同步记一行 `⚠ 打码失败（大族打标机）：原因`。

#### （4-1）打码失败弹窗

自动运行中，打标机的三步指令（① 初始化模板 → ② 下发数据 → ③ 启动打标）**每一步都要求回执带 OK**（如 `$Initialize_OK`）。指令与回执均按大族标准帧 **0x02(STX) + ASCII + 0x03(ETX)** 收发，回执按 0x03 截断后取正文（配置项 `LaserFrameEnabled`，默认开；设备不要求帧时可在配置页关掉）。任一步回执为空或不带 OK，主页会弹出提示框：

| 弹窗内容 | 示例 |
| --- | --- |
| 标题 | 打码失败（大族打标机）：打标NG（回执不带 OK） |
| 打标内容 | 229926120000020800001011（24 位分段码） |
| 打码完成位 | 未写（%MW10502 保持 0） |
| 原因 | 初始化模板回执未带 OK（指令 `$Initialize_11` / 回执 `$Initialize_NG`） |
| 时间 | 2026-10-21 17:48:58 |

- **`%MW10502` 是「打码完成」信号，只写 1**。打码成功（三步回执都带 OK 且内容一致）才写 1；失败（回执不带 OK / 回执超时 / 码生成失败 / MES 异常 / 回执内容不符）**一律不写，保持 0**，原因只在弹窗、运行日志与打码流水表里体现。
- 由此带来的现场约定：**PLC 侧要对 10502 做超时判定**（建议 8~10s 未读到 1 即判打码失败），否则失败时 PLC 分不清"还没打完"和"打失败了"。
- 弹窗关闭后 3 秒内不再重复弹，避免连续多件失败时刷屏；所有失败仍会写运行日志与打码流水表。

#### （4-2）读码失败重试与弹窗

- 扫不上（枪超时 / 返回空 / 通讯异常）时**自动重扫，默认共 3 次**（配置页「最多尝试次数」「重试间隔(ms)」，默认 3 次 / 200ms）。
- 3 次都读不到 → 写 PLC `%MW10522`＝2（NG）并弹窗「读码失败（基恩士扫码枪）：未扫到」，正文含尝试次数、时间。
- 读到码但校验不过（错码 / 重码）→ **不重试**（重扫改变不了判定），直接报 2 + 弹窗说明原因（错码 / 重码 / 枪异常）。

#### （4-3）产品码是怎么来的（配置页「码规则 → 产品码分段」）

打标内容（= 产品码）由若干**可配置段按顺序拼接**，每段定长、不足左补 0、超长保留低位。
默认按客户（Susan 邮件）确认的触点元件字段表预置，合计 **24 位**：

| 段名 | 取值方式 | 取值 / 格式 | 定长 | 示例 |
| --- | --- | --- | --- | --- |
| 供应商编码 | Fixed 固定值 | `2` | 1 | `2` |
| 生产日期/天 | Time 时间格式 | `DDD`（年内天序 001-366） | 3 | `299` |
| 生产年份 | Time 时间格式 | `yy` | 2 | `26` |
| 生产时间 | Time 时间格式 | `HHmmss` | 6 | `120000` |
| 海拉零件号 | Fixed 固定值 | `02` | 2 | `02` |
| 图纸版本 | Fixed 固定值 | `08` | 2 | `08` |
| **产品批次号** | Serial 批次号/当天流水 | — | 5 | `00001` |
| 穴号 | Fixed 固定值 | `01` | 2 | `01` |
| 原材料编号 | Fixed 固定值 | `1` | 1 | `1` |

拼出来是 `229926120000020800001011`（第 299 天 / 26 年 / 12:00:00 / 批次 00001）。

- **产品批次号 = 5 位数字，每天早上 8 点清零**（客户确认）：同一生产日内首件 `00001`、次件 `00002`……；
  00:00-07:59 打码的产品仍算前一个生产日、批次号继续累加，08:00 第一件重新从 `00001` 开始。
  清零时刻可在配置页「批次号清零(点)」改（`SerialResetHour`，默认 `8`，`0` = 自然日零点清零）。
- 批次号基于已落库的码索引算出（`ThaCodeIndex` 在本生产日窗口内的条数 + 1），所以**进程重启不会回退重号**。
- 「日期段按生产日记」勾选（`DateFollowProductionDay`，默认勾）：00:00-07:59 打码的产品日期段记**前一天**，
  同一个批次号只对应一个日期；取消勾选则日期段用实际日期，批次号仍按清零时刻归零。
- 取值方式三种：`Fixed`（固定值）、`Time`（按时间格式取，支持 `HHmmss`、`yy`、`MMdd`、`DDD`/`ddd`（年内天序）、`yyddd` 混写等）、
  `Serial`（产品批次号/当天流水，从 1 开始、每天 8 点重新计数、重启后不重复）。
- 配置页可「添加段 / 删除选中 / 上移 / 下移」，下方实时显示"当前共 N 位"和"示例：xxx"，改完点【保存配置】生效。
- **分段全部删空** → 回到旧的纯时间码模式（整码 = 「码格式」，默认 `yyMMddHHmmss`）。
- 读码站校验链随配置走：长度 = 各段定长之和 → 全数字 → 时间窗（把各 `Time` 段拼起来反解真实时间；
  日期差整天时只比时刻，不会把 00:00-07:59 的合法码误判成超窗）→ 重码状态机。

### 5.4 配置（连接设置）

> **前置条件：必须以「管理员」身份登录后方可使用（密码 2026）。** 程序启动默认为操作员身份，点击【配置】页签会被拦截，并弹出提示引导前往【人员 → 身份登入】登录。

本页用于修改 PLC 通讯参数。

| 输入项          | 说明             | 填写要求                           |
| ------------ | -------------- | ------------------------------ |
| **PLC IP地址** | 检测设备 PLC 的网络地址 | 不能为空。示例：`192.168.1.10`         |
| **PLC端口**    | PLC 通讯端口       | 必须为 **1~65535** 之间的整数，默认 `502` |
| **报表目录** | 每日追溯报表输出目录 | 默认 `D:\追溯数据`；可点【浏览…】选择；目录不存在会自动创建 |
| **数据保留(天)** | 本地数据滚动保留天数 | 默认 `30`，`0` = 永不删除；退出时检查，有旧数据才弹窗清理 |
| **写盘间隔(秒)** | 报表写盘节奏 | 默认 `60` 秒 |

| 按钮名称     | 用途                           | 正确使用方式                                                                                                               |
| -------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **保存配置** | 保存 PLC 地址与端口（以及报表/保留期设置），并让采集服务使用新地址自动重连 | 1. 填写 IP 与端口；2. 点击【保存配置】；3. 成功后提示"配置保存成功，PLC 服务将使用新地址重连"；4. **无需重启程序**，采集服务会在下一轮循环自动使用新地址重连（建议重连后回主页确认"连接状态"变为"已连接"） |

**校验与提示**

- 端口非数字或超出 1~65535 → 提示"PLC端口号无效，请输入1-65535之间的数字"，配置不会保存。
- IP 地址为空 → 提示"PLC IP 地址不能为空"，配置不会保存。
- 保存失败 → 提示具体失败原因，详见操作日志。
- 参数被实际修改时会自动写入操作日志（记录修改前后的值），便于后续追责与核对。

## 九、常见问题排查（业务视角）

| 现象                    | 排查步骤                                                                                                    |
| --------------------- | ------------------------------------------------------------------------------------------------------- |
| **PLC 连接失败**          | ① 检查 PLC 是否通电、网线是否插好；② 进入【配置 → 连接设置】核对 IP 与端口；③ 确认本机与 PLC 在同一网段；④ 查看运行日志中的错误信息；⑤ 系统每 3 秒自动重连，网络恢复后会自动恢复 |
| **数据不更新**             | ① 看主页 PLC 状态卡是否显示"已连接"；② 进【监控】页确认"上位机心跳"有变化；③ 确认 PLC 是否发起采集请求（"采集触发"有无 0→1→0 变化）；④ 查看运行日志是否有错误          |
| **界面数值异常**（如出现极小量级数值） | 属于浮点字序解析与 PLC 不匹配，**请勿自行处理**，联系厂商切换字序设置                                                                 |
| **配置页打不开**            | 需先去【人员 → 身份登入】以管理员身份登录（密码 2026）                                                                          |
| **导出无反应 / 提示没有数据**    | 确认统计页已勾选【详细数据】、已选择正确日期并且该日确实有检测记录                                                                       |
| **追溯查不到记录**           | 确认产品码输入完整且与数据库保存值一致；确认该产品确实在本机检测过                                                                       |
| **软件反复弹出授权窗口**        | 授权已到期，联系供应商获取激活码（`ZC0001` 续 60 天 / `ZC0000` 永久），在弹窗中输入并点击【激活】                                           |

## 十、待确认与已知情况（建议在定稿操作手册前核对）

以下为整理过程中发现的**界面实现与文案不一致或未接入**的情况，建议确认后统一口径再写入正式手册：

1. **「消息 / 操作记录」页面当前无入口**：菜单配置中定义了"消息 → 操作记录"（调试日志查询页），但顶部页签中没有对应的"消息"页签，操作人员目前**无法从界面进入该页面**。若操作手册需要写"查看日志"，需先确认入口。
2. **主页历史记录条数**：实际实现为内存保留 200 条、启动预载 200 条；内置帮助文字写的是"最多 500 条 / 预载 50 条"，两者不一致，应以 200 条为准或统一文案。
3. **班次口径不一致**：主界面班次显示按 8:00 / 20:00 划分；统计页白班/晚班按 8:30 / 20:30 划分。同一份手册中若同时描述，需明确区分。
4. **监控页"站别模式"显示为空**：该显示项当前未取到实际值（站别固定为 `All`），对外说明时建议只描述"站别固定为 All，不再弹出选择"。
5. **打印错误提示框（重新打印 / 取消）未接入业务流程**：界面中保留了该对话框，但当前版本没有任何业务操作会触发它，操作手册中**不必写打印相关操作**。
6. **配置项开放范围**：目前【配置】页仅开放 PLC 的 IP 与端口；配置文件中的其他项目（设备品牌、MES 地址、喷码机地址等）**未提供界面修改入口**，如需调整须由厂商处理。
7. **导出列头细节**：内置帮助文字写"鱼眼针高 1~4 / 框口针高 1~4"，实际导出为 **1~8**，以实际导出文件为准。
